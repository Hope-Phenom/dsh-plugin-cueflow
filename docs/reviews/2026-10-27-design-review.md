## 2. 发现的问题与修正

### P1 · 次级文档数量不一致

- **位置**：`10-implementation-plan.md` §7。
- **问题**：写“9 篇次级文档”，实际 `01`–`11` 共 11 篇。
- **修正**：改为“11 篇次级文档”。
- **影响**：仅文档；无代码影响。

### P2 · `{{json ...}}` 的 MVP 状态含糊

- **位置**：`05-node-reference.md` §3.2。
- **问题**：写成“MVP 可选，未实现则按普通字符串处理”，容易被误读为已支持。
- **修正**：明确标为“**不在 MVP**；遇到时保留原样，不特殊处理”。
- **影响**：实现不处理该语法；测试覆盖“未知占位符保留”。

### P3 · 面板入口的导航动作需要联调确认

- **位置**：`02`/`08`/`decisions` D-003。
- **问题**：sidebar panellist 的 id 与 main key 的对应关系来自 slot catalog 的说明；实际点击是否自动 `selectPanel` 需要真实 DSH 验证。
- **修正**：在 D-003 的“待验证清单”中加入；如果点击不自动切换，在 icon 组件里调用 `ctx.layout.selectPanel('cueflow')`。
- **影响**：Client 注册逻辑；已记录为 provisional 验证点。

### P4 · `commands.execute` / `shell.result` / `subagent childId` 的形状不确定

- **位置**：`08`、`decisions` D-008/D-009。
- **问题**：文档给了理想形状，但本机 DSH 版本可能不同；如果强绑定，真实环境会失败。
- **修正**：
  - 适配器统一防御性读取；
  - 失败时记录 `adapter:fallback`；
  - 在决策表中标 `provisional`，并列出失败后的替代方案；
  - 不把“真实 DSH 已验证”写进状态。
- **影响**：`lib/core/adapters.js` 的兼容分支与测试。

### P5 · 运行失败时是否取消正在运行的节点

- **位置**：`07` §6。
- **问题**：初稿只说“停止启动新节点”，没有明确正在运行的节点怎么办。
- **修正**：明确 MVP **不主动取消**正在运行的节点，避免半截副作用；用户取消才全部取消。文档已补。
- **影响**：executor 的 fail-fast 实现。

### P6 · 画布多选/框选的范围

- **位置**：`06` §4、`10` §4。
- **问题**：交互表写了“Shift+点击”“框选”，但 MVP 任务没有明确是否实现，容易造成验收争议。
- **修正**：明确 MVP 为**单选 + 快捷键**；Shift 多选/框选标为 M5。节点仍支持 Tab 遍历。
- **影响**：Client 交互范围。

## 3. 自审结论

- 文档体系满足“主文档 + 次级文档 + 决策表”的要求，主文档不会随迭代无限膨胀。
- 关键未知点已显式标为 provisional，而不是伪装成确定事实。
- 节点规格与执行语义足以直接指导实现；下一步按 `10-implementation-plan.md` 的 M2/M3/M4 推进。
- 待真实 DSH 验证的 5 项（D-003 导航、D-008 命令、D-009 子代理、D-006 轮询体验、D-013 bundle 形态）不会阻塞 L1–L3；L4 前必须逐项确认。
